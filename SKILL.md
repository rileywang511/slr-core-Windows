# slr — reproducible systematic literature review CLI

## When to use

Use this skill when the user wants to run any part of a systematic literature
review pipeline:
- Search bibliographic databases for a topic (OpenAlex, Europe PMC, PubMed,
  Crossref, optionally Scopus / Web of Science)
- Build a PRISMA flow diagram from search to inclusion
- Deduplicate results across multiple databases
- Screen records by inclusion/exclusion criteria (rule-based or LLM)
- Retrieve open-access PDFs via OA aggregators
- Convert PDFs to Markdown for full-text screening
- Export an included set to RIS for Zotero/Rayyan/Covidence

Do **not** use this skill for ad-hoc "find me a paper" lookups; this is a
batch, audit-logged workflow.

## The review directory

A "review" is a single directory. Everything for one review lives there:

```
my-review/
├── protocol.yaml          # METHODOLOGY (share with collaborators)
├── config.yaml            # SYSTEM SETTINGS (per-machine; safe to .gitignore)
├── audit.log.jsonl        # append-only log of every command + tool version
├── records.csv            # one sanitised, deduplicated paper per row
├── evidence.jsonl         # append-only source runs, occurrences, warnings/errors, dedup decisions
├── screen_*.csv           # screening decisions per stage (appended live)
├── fetch_attempts.csv     # OA resolver attempts (+ fulltext_conversions.csv)
├── _state.json            # per-stage completion + input/output hashes
├── pdfs/                  # downloaded OA PDFs (readable title/year + record ID)
├── markdown/              # cached converted text: <stem>.<engine>.md
├── prisma.json            # canonical PRISMA counts
├── prisma.mmd             # Mermaid diagram source
├── prisma.svg             # rendered if mmdc is on PATH
└── exports/               # included.ris, all.jsonl, screened.csv, ...
```

**Two human-authored files**:
- **`protocol.yaml`** is the methodology — query, sources, criteria, dedup
  threshold, and per-stage screening *type* (`llm` / `rules` / `manual`).
  This is the file that travels with the review for PRISMA reproducibility.
- **`config.yaml`** is the environment — `contact_email` (Unpaywall),
  per-stage LLM provider details (provider/model/base_url), fulltext
  resolver chain, optional institutional proxy, marker-pdf settings, HTTP
  retries. Optional; sensible defaults apply if it's missing.

`records.csv` is the final list of unique papers. `evidence.jsonl` preserves
each source occurrence and original payload, every matching decision (method,
score, and selected source occurrence), and one event per warning/error. This
makes deduplication and imperfect imports reviewable without duplicating papers
in the main file.

Older reviews are migrated into the ledger on first access. Their original
evidence artifacts are retained untouched for comparison; new reviews create
only `records.csv` and `evidence.jsonl` for ingestion and deduplication.

`slr init` scaffolds both with annotated examples. The stage CSVs are
regenerated by their commands — **prefer re-running a stage over hand-editing
its CSV.** Every command appends to `audit.log.jsonl` so the full history is
recoverable from output alone — the screener id (provider + model) is
logged per decision, so config.yaml doesn't need to be shared to reproduce
the PRISMA flow.

Stage dependencies are tracked explicitly (`search → dedup → title/abstract
screening → fetch → full-text screening`). Re-running a changed stage clears
its derived outputs and completion markers, so `slr inspect` points to the
first affected command rather than treating stale work as current.

## Workflow (canonical order)

1. `slr init <dir>` — scaffold a fresh directory with an example
   `protocol.yaml`. Tell the user to edit it before continuing.
2. `slr search <dir>` — run every source listed under `sources:`. Use
   `--limit N` for quick testing; remove for the real run.
   *Alternative*: if the user already has CSV / RIS exports from a database
   web UI, use `slr import <dir> <file>` (one or more times) instead of /
   in addition to `slr search`. See "Importing exports" below.
3. `slr dedup <dir>` — exact DOI grouping, then conservative fuzzy
   title/author/year matching for DOI-missing evidence and remaining records.
4. `slr screen <dir> --stage title_abstract` — apply the configured screener
   to each final record's title and abstract.
5. `slr fetch <dir>` — run the OA resolver chain (OpenAlex → Unpaywall →
   Europe PMC → Semantic Scholar → CORE → BASE → OpenAIRE → optional proxy)
   for records that passed title/abstract. Writes per-record progress to
   stderr and, on completion, a `unresolved.csv` listing every paper that
   couldn't be obtained automatically, plus a status table summarising the
   run.
6. **Manual collection step.** Each row in `unresolved.csv` has a `save_as`
   column with the exact readable filename to use for that record. Workflow: download the PDF from the `doi_url` or `url` column,
   then save it into the review's `pdfs/` directory under the `save_as`
   filename verbatim — do NOT rename. `slr screen --stage full_text`
   auto-detects placed files on its next run; no separate ingest command.
   *Alternative*: `slr request-reprints <dir>` produces templated emails to
   corresponding authors. Sci-Hub / piracy mirrors are not used.
7. `slr screen <dir> --stage full_text` — apply the configured full-text
   screener. There is **no separate convert step**: PDF conversion happens
   inline, controlled by `screen.full_text.converter` (override per run
   with `--converter`):
     - `marker` (default) — marker-pdf converts each PDF to markdown locally;
     - `pdf-inspector` — Firecrawl's local layout-aware PDF -> Markdown engine;
     - `anydoc` — Firecrawl's local document-to-Markdown engine;
     - `extend` — Extend Parse 2.0 API converts it (needs `EXTEND_API_KEY`);
     - `datalab` — Datalab Marker API, hosted marker (needs `DATALAB_API_KEY`);
     - `server` — your own self-hosted marker server (see `slr marker-server`),
       endpoint + token from `MARKER_SERVER_URL` / `MARKER_SERVER_KEY`;
     - `none` — the raw PDF is sent to the model (needs a PDF-capable provider
       like Anthropic or OpenAI).
   Conversions are cached under `markdown/<stem>.<engine>.md`, so resumes and
   re-runs don't re-pay. Only the subset that passed title/abstract screening
   (TA decision = `include`) is assessed — not the whole deduplicated set.
   `fulltext: required` requires a PDF; `optional` uses a PDF when available
   and otherwise screens the title/abstract; `ignored` is deliberately
   abstract-only. Resume is automatic
   (already-decided records are skipped); pass `--restart` to redo the whole
   stage, or `--retry-errors` to re-screen only records whose conversion or
   screening previously errored (e.g. a transient `Extend API request failed`).
8. `slr prisma <dir>` — compute counts, write `prisma.json` / `prisma.mmd`
   (and `prisma.svg` if `mmdc` is on PATH).
9. `slr export <dir> --format ris --stage included` — write
   `exports/included.ris` for Zotero/Rayyan/Covidence import.
10. `slr export-included <dir>` — write `exports/included_fulltext.csv`: one row
    per study that passed full-text screening, with the PDF and markdown paths,
    the screening reasoning (decision + reason code/text + screener, for both the
    full-text and title/abstract stages), and provenance (source, IDs, which
    databases found it, the OA resolver, content hash, and converter used).

## Importing exports

If the user has already run searches in a database UI and downloaded results,
they don't need to re-run via `slr search`. `slr import` ingests:

| Format          | Source platforms                                          |
|-----------------|------------------------------------------------------------|
| `scopus`        | Scopus → Export → CSV                                     |
| `wos`           | Web of Science → Export → CSV / tab-delimited             |
| `pubmed`        | PubMed → Send To → File → CSV                             |
| `europepmc`     | Europe PMC → Export results → CSV                         |
| `openalex`      | OpenAlex → Export → CSV (web UI)                          |
| `openalex_json` | OpenAlex `/works` API JSON or JSONL bulk snapshots        |
| `ris`           | RIS from Zotero, Mendeley, EndNote, EBSCO, ProQuest, etc. |
| `csv`           | Generic CSV with `title`/`doi`/`year`/`authors` columns   |

```bash
slr import my-review scopus-export.csv                          # auto-detected
slr import my-review wos-export.csv --format wos                # explicit
slr import my-review zotero.ris --source my_curated_library     # custom label
```

`--format auto` (default) sniffs the column header to pick the right importer.
Re-importing the same file replaces its active import snapshot. Each immutable
run still retains its own source occurrences, so an earlier run can always be
audited without contaminating the current deduplication set.

Imported records become a `source_run` in `evidence.jsonl` just like API hits,
so the rest of the pipeline (`dedup`, `screen`, `fetch`, `prisma`, `export`)
works identically. Failed rows are recorded there individually with their raw
input and parser message. PRISMA's "Identification" stage counts each import
as its own source.

## Inspecting state

Always run `slr inspect <dir>` (JSON by default) before deciding what to run
next. The output reports which stages are completed, record counts, and the
next suggested command. Agents should use this as the source of truth for
where they are in the workflow.

## Authoring `protocol.yaml` (methodology)

Required fields: `review_id`, `title`, `query` (WoS-style), `sources`.

```yaml
review_id: my-review-2026
title: "..."
authors: ["Your Name"]
created: 2026-05-15
query: |
  TS=((metagenom* OR "shotgun sequencing") AND (wastewater OR sewage))
  AND PY=2015-2026
  NOT DT=Review
sources: [openalex, europepmc]              # also: pubmed, crossref, scopus, wos
date_range: { from: 2015-01-01, to: 2026-05-15 }
inclusion_criteria:
  - { id: I1, text: "Uses shotgun metagenomic sequencing" }
  - { id: I2, text: "Sample type is environmental water" }
exclusion_criteria:
  - { id: E1, text: "Review, editorial, or commentary" }
screen:
  title_abstract:
    type: llm                                # or 'rules' or 'manual'
    # provider / model / base_url live in config.yaml
  full_text:
    type: llm
    fulltext: required                       # required | optional | ignored
dedup:
  fuzzy_title_threshold: 90
```

### WoS-style query syntax

| Tag    | Meaning                                  |
|--------|------------------------------------------|
| `TS=`  | topic — searched across title/abstract   |
| `TI=`  | title only                               |
| `AB=`  | abstract only                            |
| `AU=`  | author                                   |
| `PY=`  | publication year (single or `2015-2026`) |
| `SO=`  | source/journal                           |
| `DT=`  | document type (e.g. `Review`)            |
| `LA=`  | language                                 |

Operators: `AND`, `OR`, `NOT`, `NEAR/n`, parens for grouping, `"phrases"`,
`*` and `?` wildcards. Each source has its own dialect; the tool translates
and logs warnings for any feature that couldn't be expressed faithfully.

Live PubMed searches enrich ESearch IDs with EFetch XML, including abstracts
and article identifiers. If an EFetch batch fails, the CLI emits a warning and
falls back to ESummary metadata for that batch; abstracts may then be missing.

## Authoring `config.yaml` (system settings)

Optional — defaults apply if absent. Settings are grouped by the command that
uses them: `search` for scholarly-source access, `screen` for LLM screening,
and `fetch` for PDF acquisition/conversion. Configuration is strict: each
documented field has a runtime effect, and unknown or retired keys are
rejected. Commands with no durable machine setting — including `import`,
`dedup`, `export`, `prisma`, and `inspect` — intentionally have no empty
section; their settings belong in `protocol.yaml` or their command options.

```yaml
search:
  contact_email: you@example.com              # required by Unpaywall; shared with fetch resolvers
  http:
    max_retries: 5
    base_delay: 1.0
    max_delay: 60.0
screen:
  title_abstract:
    provider: anthropic                       # anthropic | openai | openai-compatible
    model: claude-sonnet-4-6
  full_text:
    provider: anthropic
    model: claude-sonnet-4-6
    converter: marker                         # marker | pdf-inspector | anydoc | extend | datalab | server | none
fetch:
  sources: [openalex_oa_url, unpaywall, europepmc_oa, semantic_scholar, core, base, openaire]
  cache_dir: pdfs/
  markdown_dir: markdown/
  max_mb_per_pdf: 25
  proxy:
    enabled: false                            # set true + url for institutional access
    url: https://login.ezproxy.your.uni/login?url={target}
  marker:                                     # converter: marker
    use_llm: false                            # marker-pdf hybrid mode
    force_ocr: false                          # for scanned PDFs
    isolate: true                             # run marker in a recycled child process
    recycle_after: 50                         # restart it every N PDFs to bound RAM
  pdf_inspector:                              # converter: pdf-inspector (local)
    use_ocr: false                            # selective local OCR for scanned/mixed PDFs
    # model_directory: /opt/models/pp-ocrv6-small
    # offline: true                           # require local OCR artifacts; no model download
  extend:                                     # converter: extend (needs EXTEND_API_KEY)
    target: markdown
  datalab:                                    # converter: datalab (needs DATALAB_API_KEY)
    mode: balanced                            # fast | balanced | accurate
  server:                                     # converter: server (self-hosted marker)
    url_env: MARKER_SERVER_URL                # set this env var to your server URL
    api_key_env: MARKER_SERVER_KEY            # optional bearer token
```

### Full-text conversion (`screen.full_text.converter`)

PDF → model input happens during `slr screen --stage full_text` (no separate
convert step). Override per run with `--converter`:
- `marker` (default) — marker-pdf converts to markdown locally (`pip install 'slr-agent[marker]'`).
  marker/surya leak native memory over long runs, so by default it runs in a
  child process that is **recycled every `fetch.marker.recycle_after` PDFs**
  (default 50) to cap RAM; set `fetch.marker.isolate: false` to run in-process.
  Set `SLR_MARKER_DEBUG=1` to see marker's own output (otherwise the child is quiet).
- `pdf-inspector` — Firecrawl's fast local, layout-aware PDF -> Markdown engine
  (`uv pip install -e '.[pdf-inspector]'`). It needs no OCR runtime for
  native-text PDFs. Set `fetch.pdf_inspector.use_ocr: true` for its
  selective local OCR path; that additionally requires PDFium, ONNX Runtime,
  and OCR model artifacts. Use `model_directory` plus `offline: true` to
  prohibit model downloads.
- `anydoc` — Firecrawl's local document-to-Markdown serializer
  (`uv pip install -e '.[anydoc]'`). Its PDF support uses native extraction;
  use `pdf-inspector` with OCR or `marker` for image-only/scanned PDFs.
- `extend` — Extend Parse 2.0 API; set `EXTEND_API_KEY`. Funnels parsed markdown into the model.
- `datalab` — Datalab Marker API (hosted marker, no local models/RAM); set `DATALAB_API_KEY`.
- `server` — your own marker box. Run `slr marker-server` on a machine with marker
  installed; clients set `MARKER_SERVER_URL` (and `MARKER_SERVER_KEY`) and need no
  marker/torch locally. The server runs marker through the same recycled child
  process, so its memory stays bounded. Start it with:
  `MARKER_SERVER_KEY=secret slr marker-server --host 0.0.0.0 --port 8000`.
- `none` — send the raw PDF to the model; requires a PDF-capable provider (Anthropic/OpenAI).

### LLM provider configuration

Three options per stage (under `screen.<stage>` in **config.yaml**):
- `provider: anthropic` — uses `ANTHROPIC_API_KEY`. Prompt caching enabled.
- `provider: openai` — uses `OPENAI_API_KEY`.
- `provider: openai-compatible` — uses `base_url` for the endpoint
  (Ollama: `http://localhost:11434/v1`, vLLM, llama.cpp server, LM Studio).

Verify the endpoint and model name with **`slr llm test <dir>`** before
kicking off a long screening run — it sends a single probe to the
configured provider for the chosen stage (defaults to `title_abstract`) and
reports the parsed decision, latency, and (if applicable) a hint when the
model fails to produce JSON.

## Screening is resumable

`slr screen` appends each decision to the stage CSV **immediately** after the
screener returns, not at the end of the run. Practical implications:

- If a screening run is killed (Ctrl-C, process crash, the LLM endpoint
  going down, laptop sleep, etc.), all decisions made so far are preserved.
- Re-invoking `slr screen <dir> --stage <stage>` automatically resumes from
  where it stopped — it skips records that already have a decision for
  that stage. The progress banner announces this:
  `[title_abstract] screening with claude-sonnet-4-6: 247 pending, 753 already decided (resuming) of 1000 total records`.
- Cumulative tally lines reflect previously-decided counts as well, so the
  numbers stay meaningful across multiple sessions.
- The final summary's `n_decided_this_run` field tells you how much work
  this invocation actually did (vs. resumed from disk).

To re-screen everything from scratch (e.g. you changed criteria or the
protocol's `screen.<stage>.type`), pass `--restart`. That wipes the
stage's existing decisions and starts over.

## When something fails

- Every command supports `--json` and uses stable exit codes:
  `0` success, `1` config/input error, `2` upstream stage missing,
  `3` stale-input refusal.
- Inspect `audit.log.jsonl` — every entry has tool version and input/output
  hashes.
- Re-running a stage with unchanged inputs is a no-op; safe to retry.
- With `converter: marker`, if marker-pdf isn't installed, full-text screening
  records a conversion error per PDF telling you to `pip install 'slr-agent[marker]'`
  (switch to `--converter extend` or `--converter none` to avoid the local dep).
- If LLM providers aren't installed, `slr screen` will tell you to
  `pip install 'slr-agent[llm]'`.

## Things this skill won't do

- Search behind paywalls without your institutional credentials.
- Use Sci-Hub or any mirror site that redistributes copyrighted PDFs. The
  `slr request-reprints` workflow is the legitimate alternative.
- Run screening without a `protocol.yaml` committing inclusion/exclusion
  criteria upfront (so the reasoning is auditable).
- Skip the audit log.

## Reproducibility guarantee

Anyone with the review directory can reconstruct the entire PRISMA flow from
`protocol.yaml` + `prisma.json` + `records.csv` + `evidence.jsonl` + the stage
CSVs. To share a review for peer review, share the directory. To reproduce it
independently, start a new review from the shared protocol and compare the
resulting `prisma.json` files.
